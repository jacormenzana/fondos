## 5. Traps found (all fixed or documented)
- A fixed-size assumption in a test breaks when the repo grows (the 500 s weight): when a full receipt fails on a test the change did not touch, count the files / rows it depends on before suspecting the change.
- `LeverConfig.key()` must stay byte-identical for a config that uses no new lever (warm score caches are keyed on it); a legacy-key test pins it. New levers go through `any_on` (cache key) and `uses_inputs` (the PIT inputs): an L5/L6-only run needs no `lever_inputs`.
- The fee-penalty shadow refuses to mix arms when another lever is ON (`other_levers_on` counts L5 and L6).
- Cold PIT arm = about 8 min, warm = about 76 s; a sample smoke (`--sample-per-nature 4 --no-short-gates`) takes about 40 s and is never a result.
- Patch scripts written through a bare Bash heredoc lose backslashes (`"\n"` became a real newline once); write them with the Write tool.
- The `Closes:` commit of a ticket closes it only after a passing receipt; a receipt that fails leaves it IN_PROGRESS (nothing is lost); re-point the closing condition to the fix commit.
